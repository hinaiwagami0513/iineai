## 2. カラー

> ### ⛔ 大前提：色の正は「既存 HP の実レンダリング」。CSS でもボードでもない。
>
> **現行 HP は事実上モノクロ。** ブランドの色に相当するものは、UI ではなく**素材テクスチャ（デニムフェルト）**が担っている。
> CSS に緑 `#0a9f7a` が書かれているが、**画面上ではほぼ出ていない**（→ 2-2）。参考ボードの緑も採用しない。
> 検証方法：`index / about / product / company / contact` の5ページを 1280px でレンダリングし、
> ①可視要素の computed style を面積加重で集計 ②スクリーンショットの実ピクセルを k-means 抽出、の2系統で突き合わせ。

### 2-1. 実際に使われているパレット（確定）

| 役割 | 値 | 出どころ |
|---|---|---|
| **本文・見出し・罫・ロゴ** | `#000000` | 全5ページで最大の前景色。**純黒** |
| 見出し墨 | `#303030` | `h3` / `.Lttl`。見出し下に 80×3px の短い罫 |
| 補助テキスト | `#333333` | index の一部 |
| 罫（中） | `#939393` | company の区切り線 |
| 罫（細） | `#ececec` | contact の細罫 |
| セクション地 | `#f5f5f5` / `#f7f7f7` | NEWS ほか各セクション |
| 地 | `#ffffff` | 全ページのベース |

**有彩色は画面の 2.5〜10% しかなく、その大半は写真。** UI としての色は上記の無彩色ラダーだけ。

### 2-2. 緑 `#0a9f7a` は「CSS にあるが使われていない」

実レンダリングで緑が出るのは **index ページのこれだけ**：

| 要素 | サイズ | 出方 |
|---|---|---|
| `.btn_intro` ×3（英語版・紹介動画ほか） | 313×48 / 225×48 / 178×48 | **1px の枠線のみ** |
| `.news_top_category` ×6 | 179×27 | 小さいカテゴリチップの地 |
| `.sns_iineAI` | 677×60 | 1px 枠 |

about / product / company には**1ドットも出ない**。contact に別変種 `#00aa7c` が微量。

→ **緑はブランドカラーとして機能していない。** 制作物で緑を使うのは「新しく色を足す」判断になる。

### 2-3. ★ 実質のブランド要素は「フェルトバー」

全ページ最上部に `DIV.feltbar`（1280×30px）があり、`img/shared/img_felt.jpg`（2480×254）を敷いている。**デニムフェルト素材そのものの写真。**

| 抽出色 | 面積 | HSL |
|---|---|---|
| `#455877` | 32.1% | H217 S27 L37 |
| `#4e6485` | 27.6% | H216 S26 L41 |
| `#3c4d69` | 22.4% | H217 S27 L32 |
| `#647a99` | 9.2% | H215 S21 L50 |
| `#303f58` | 8.7% | H218 S29 L27 |

**H215–218 / S21–29 / L27–50 に完全に収束**。代表値 `#455877`。

そして contact の `.btn_download` に使われている紺 `#2f466f`（H218 S40 L31）は、**このフェルトの色相とほぼ同じ**。偶然ではなく、素材の色から引いてきたと考えるのが自然。

→ **このサイトで唯一機能している「色」は、素材由来のデニムブルー。** しかも面ではなくテクスチャとして入っている。knowledge.md §11 の「素材の質感が最大の訴求要素」と完全に一致する。

### 2-4. ロゴはモノクロ

`img/shared/guc_logo.svg`（黒）と `guc_logoW.svg`（白）の2版のみ。SVG 内に fill 指定が無く、**マーク自体に色が入っていない**。どんな地にも載る。

### 2-5. 整理対象（体系から外れている色）

`#4a3114` 茶（`.btn_wdauto` ボタン地）／`#623416` 茶（`.newstitle`）／`#2f466f` 紺（`.btn_download`、ただし 2-3 の通りフェルト由来なら残す価値あり）／`#0a9f7a` 系の緑3変種（`#0a9f7a` `#0aa07a` `#0ba07a`）。ブランディング確定時に取捨を決める。

### 2-6. ボードの色は使わない

参考ボードの深緑（`#36654c` ほか）は**構図を読むために抽出しただけ**で、配色としては採用しない。ボードから持ってくるのは**構図・レイアウト・写真の扱いだけ**。

### 2-7. ボードのニュートラル（＝素材そのものの色。写真として入る）

| 系統 | ボード抽出値 | 備考 |
|---|---|---|
| ベージュ／タン | `#bcac90` `#bfb3a3` `#a68a77` `#c6a28e` | 麻素材の色 |
| グレー | `#d6d6d6` `#b2b5b4` `#b9c0b8` | カスタム素材の色 |
| ネイビー | `#0c3352` `#305899` | デニム素材の色 |
| オフホワイト | `#e7e9de` `#efece9` `#f9f7f8` | ボードは暖色寄りの白。ただし **HP の地は `#ffffff`。正は HP** |

`green-upcycle-knowledge.md` §4 の素材3系統と、ボードのニュートラルが一致する。ただしこれらは**写真の中に現れる色であって、グラフィックの塗り色として新たに採用するものではない**。

ボードのネイビー（`#0c3352` `#305899`）は、HP の feltbar（`#455877` 系 / 2-3）と同じデニム由来。**素材の色は媒体をまたいで一致している**ので、ここは信用してよい。

**運用は2層で分ける：**

- **UI 層（塗り・文字・罫）** → `#000000` / `#303030` / `#939393` / `#ececec` / `#f5f5f5` / `#f7f7f7` / `#ffffff` の**無彩色のみ**
- **素材層（写真・テクスチャ）** → デニムブルー（`#455877` 系）／ベージュ／グレー。**色はここだけから出す**

knowledge.md §11 の「任意のブランドカラーを素材に載せられない」という制約はここで守られる。**UI に色を足さず、色は素材の側から出す。**

## 3. レイアウトの共通則

8枚から抜いた、繰り返し出てくる構造。

### 3-1. ベタ1色の背景に切り抜き被写体（pin-2 / 3 / 8）
写真を四角のまま置かず、必ず背景から切り抜いて単色地に浮かせる。写真の矩形が見えてる面は1枚も無い。

### 3-2. タイポと写真のレイヤー交差
- pin-8：`STORE` の `RE` が写真に隠れて線画（アウトライン）に変わる
- pin-7：ロゴを文字抜きにして、その穴から藍染写真が見える
- pin-1：タイトルと被写体が重なるギリギリまで寄せてる

**文字を写真の「上」に置くだけで終わらせない。** 交差・貫通・抜きのどれかを1回入れるのがこのボードの型。

### 3-3. 情報ブロックは端に小さく固める
日時・会場・主催などの細かい情報は、必ず端に縦一列でまとめて、主役の面積を殺さない。

- pin-1：左上に日本語明朝の小さい塊
- pin-4：左端に日付を縦組み
- pin-8：下端3カラムの小さい和文

### 3-4. 中央対称はゼロ
8枚とも重心がオフセンター。左右対称・中央揃えのポスターは1枚も無い。

### 3-5. 余白率は2極
| 型 | ピン | 特徴 |
|---|---|---|
| 余白主導 | 3 / 7 | 白が50%以上。被写体1点勝負 |
| 塗り主導 | 2 / 8 | 地色が画面の40〜60%。文字がデカい |

中間（ほどよく要素が散った版面）は無い。**どっちかに振り切る。**

## 4. タイポグラフィ

- **見出しは極太サンセリフ。** pin-2（コンデンス寄り）、pin-8（縦積みの極太ゴシック）。ウエイトは Bold では足りず Black / Heavy 帯
- **和文は明朝とゴシックの併用。** pin-1 は英字が丸みのあるサンセリフ、和文が細い明朝。pin-4 は和文縦組み
- **サイズのジャンプが激しい。** 見出しと本文の間に中間サイズを置かない。1枚の中で 2〜3 段階のみ
- **縦組みが有効。** pin-4 / pin-7 が縦組み。和文素材事業として日本的な文脈と相性が良い
- 装飾書体・手書き風スクリプトは0枚

## 5. ⚠️ 方向性が割れてる2枚（要確認）

**pin-5（Classic Blue）と pin-6（幾何パターン壁紙）だけ、他の6枚とトーンが繋がってない。**

- pin-6 の主色 `#eb9760` は H24 **S78** L65。他ピンの彩度30%前後に対して**倍以上の彩度**
- 両方ともバウハウス系の幾何抽象で、「素材の質感を見せる」という事業の核（knowledge.md §11）と逆方向
- 写真を1枚も使ってない

**解釈は2通り：**
1. パターン／テクスチャの参考として別枠で保存した（＝メインの方向性ではない）
2. 幾何パターンもブランドの引き出しとして入れたい

どっちかで作るものが変わるので、**ピンが増えて幾何系がもう数枚入るなら 2、増えないなら 1** と判断する。現時点では 1 として扱い、メイン方向性からは除外して §2〜4 を算出した。

## 6. 更新手順（ピン追加後にそのまま流す）

```bash
B="$HOME/.claude/skills/gstack/browse/dist/browse"
D=<scratchpad>/guc-pins && mkdir -p "$D"
$B goto "https://jp.pinterest.com/gr5342/green-up-cycle/"
$B media --images | grep -o 'https://i.pinimg.com/736x/[^ ]*\.\(jpg\|png\)' | sort -u > "$D/urls.txt"
i=1; while read -r u; do curl -s -o "$D/pin-$i.jpg" "$u"; i=$((i+1)); done < "$D/urls.txt"
# パレット抽出（sips で 64px BMP 化 → 純Python k-means）
for f in "$D"/pin-*.jpg; do sips -Z 64 -s format bmp "$f" --out "${f%.jpg}.bmp" >/dev/null; done
python3 palette.py "$D"
```

注意：Pinterest は**スクロールしないと全ピンの img が DOM に出ない**。ピンが20枚を超えたら `$B js "window.scrollTo(0,document.body.scrollHeight)"` を数回挟んでから `media --images` を叩く。

## 8. 制作時のチェックリスト

作ったものをこの8項目で照合する。

- [ ] UI（塗り・文字・罫）に有彩色を1つも足していないか
- [ ] 使った無彩色が `#000000` `#303030` `#939393` `#ececec` `#f5f5f5` `#f7f7f7` `#ffffff` に収まっているか
- [ ] 色は素材（フェルトのテクスチャ・写真）から出しているか
- [ ] 緑を足していないか（現行 HP では機能していない色）
- [ ] ボードから色を拾っていないか（ボードは構図の参考であって配色の参考ではない）
- [ ] 写真を矩形のまま置いてないか（切り抜いたか）
- [ ] タイポと写真の交差・抜きを最低1回入れたか
- [ ] 細かい情報を端に固めて主役の面積を守れてるか
- [ ] 中央対称になってないか
- [ ] 余白主導か塗り主導、どっちかに振り切れてるか（中途半端でないか）
- [ ] 素材の質感が写真で伝わるか（CG・イラストで代替してないか / knowledge.md §11）
