# brand-rename-pending（ブランドが確定するまで作り込まない）

> 8/28: **サービス名「いいねAI」とメインカラーが変わる可能性**がある。確定まで、名前と色に縛られる制作物には時間をかけない。

## 何が未確定か（8/28・佐藤）
- **サービス名称**。佐藤「もし『いいね』っていう名前じゃなくなって別の名前になった時は」。
- **メインカラー**。オレンジのままとは限らない。
- **確定時期**: 来週〜9月中旬。「変わるなら変わるって決まります、そこで」。

## だから止めるもの / 止めないもの

| | 判断 | 理由 |
|---|---|---|
| キャラクター（🦊）の作り込み | **止める** | 狐の**お腹に「いいねAI」と書いてある**。名前が変わると作り直しになる |
| ロゴ制作 | **止める**（確定後に着手） | 同上 |
| サービスサイトの構成・制作 | **止める** | 名前と色が前面に出る。[[service-website]] |
| 本体UIの色 | **止めない** | DESIGN.md の primary / secondary を差し替えるだけで通る |
| 本体UIの機能・スマホ対応 | **止めない**（最優先） | ブランドと独立。8/28の最優先事項 |

## 色替えが安いのはトークン設計のおかげ
岩上「デザインMDでプライマリーを変えるだけなので」「UIの方はマジですぐ色変えられると思ってます」。
DESIGN.md → globals.css の一方向生成で、色がセマンティック名に閉じているから成立する（[[design-tokens]]）。
**この前提を崩す作り方（生の16進をワイヤーに直書きする等）をしない**。

## 現キャラの位置づけ
岩上「仮でささっと作ったキャラクターだったのであんまり愛着ない。ちゃんとオリジナルで私が手で作ったやつにしたい」。
→ 現行の狐は**仮**。作り直す前提なので、これを基準に他の画面を寄せていかない。

## 解除の合図
佐藤から名前・カラーの確定連絡が来たら、ロゴ → キャラクター → サービスサイトの順で着手する。
